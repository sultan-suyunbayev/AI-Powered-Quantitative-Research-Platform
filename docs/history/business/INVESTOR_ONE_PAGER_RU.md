## Суть продукта в одном предложении

> CustodiaCloud — это B2B risk-first платформа для исследований и деплоя систематических торговых стратегий, построенная на архитектуре CCEA, где исполнение и секреты остаются под контролем клиента.

---

## Проблема

Профессиональные систематические команды (проп-фирмы, небольшие фонды) тратят **месяцы и сотни тысяч евро** на построение инфраструктуры до запуска первой стратегии:

| Текущая реальность | Боль клиента |
|---|---|
| Фрагментированный toolchain | Отдельные системы для бэктеста, исполнения, мониторинга |
| Долгий time-to-market | 3-12 месяцев от идеи до продакшна |
| Высокие затраты на инфраструктуру | €500K-2M на in-house разработку |
| Слабые риск-контроли | Ручной контроль, постфактум-алерты |
| Governance-пробелы | Нет evidence-пакетов для procurement |

---

## Решение: CustodiaCloud

Платформа, которая сокращает путь от исследований до контролируемого деплоя с **днями вместо месяцев** (цель, подлежащая валидации через пилоты).

### Архитектура CCEA (Cloud-Controlled Execution Architecture)

```
┌─────────────────────────────────────────────────────────────────┐
│                        CLOUD (Наша инфра)                        │
│  Research IDE │ Backtest & Sim │ Artifact Registry │ Monitoring │
│                                                                   │
│  НЕ хранит: секреты │ НЕ отправляет: live-ордера/сигналы        │
└───────────────────────────────────┬───────────────────────────────┘
                                    │ Lifecycle-команды
                                    ▼
┌─────────────────────────────────────────────────────────────────┐
│                        AGENT (Инфра клиента)                     │
│  Local Vault │ Risk Manager │ Kill Switch │ Broker Connector    │
│                                                                   │
│  Секреты локально │ Ордера локально │ Клиент контролирует        │
└─────────────────────────────────────────────────────────────────┘
```

**Ключевое преимущество CCEA**:

- Cloud **не хранит** API-ключи клиента
- Cloud **не отправляет** live-ордера, targets или сигналы
- Исполнение происходит **только в среде клиента** через Agent

## Почему это важно инвестору

| Преимущество | Что это означает |
|---|---|
| **Регуляторная ясность** | Software/ICT Provider — не execution service, не советник |
| **Procurement-friendly** | Секреты не покидают инфру клиента — проще для security-review |
| **Защитный moat** | Сложная архитектура + 2+ года разработки + 7+ научных статей |
| **B2B модель** | Subscription-доход, прогнозируемый ARR |

## Технологические дифференциаторы

### Инновации первого уровня (то, чего нет у конкурентов)

| Инновация | Что это даёт | Научная основа |
|---|---|---|
| **Distributional PPO + CVaR** | Оптимизация с учётом tail-риска (worst 5%), а не только среднего | Dabney et al. 2018, Chow et al. 2015 |
| **Twin Critics** | Снижение переоценки value function | Fujimoto et al. 2018 |
| **AdaptiveUPGD** | Continual learning: модель не "забывает" предыдущие режимы рынка | Kirkpatrick et al. 2017 |
| **Conformal Prediction** | Неопределённость без предположений о распределении | Romano et al. 2019 |

### Моделирование исполнения (L2/L3)

| Модель | Факторы | Источник |
|---|---|---|
| Equity TCA | 9 факторов (участие, market cap, intraday U-curve, beta stress...) | Almgren-Chriss 2001, Kissell 2013 |
| L3 LOB Simulator | Queue-reactive fill probability + market impact + dark pools | Moallemi & Yuan 2017, Gatheral 2010 |

### Покрытие активов (фундамент multi-asset, MVP = equities-first)

- Listed equities (MVP)
- Listed futures
- Listed options
- FX
- Digital assets (опционально, по юрисдикции)

## Конкурентное преимущество

| Аспект | Традиционные платформы | CustodiaCloud |
|---|---|---|
| Архитектура | Monolithic cloud execution | CCEA (Cloud/Agent separation) |
| Секреты | В облаке | Только локально у клиента |
| Цель оптимизации | maximize E[Return] | maximize E[Return] s.t. CVaR ≥ threshold |
| Моделирование исполнения | Fixed slippage (2-5 bps) | 6-9 факторов, real-time адаптация |
| Покрытие активов | 1-2 класса | 5 классов (единая кодовая база) |
| Governance | Минимальный | Evidence exports, audit trails |

### Почему мы не клон конкурентов

| Конкурент | Их фокус | Наше отличие |
|---|---|---|
| **QuantConnect** | Community + education | Institutional-grade ML + CCEA boundary |
| **Alpaca** | Broker API | End-to-end платформа с risk controls |
| **In-house** | €500K-2M, 12+ месяцев | Дни до первого бэктеста, fraction of cost |

## Регуляторное позиционирование (design intent)

| Framework | Наш подход | Что мы НЕ делаем |
|---|---|---|
| **MiFID II** | Риск-контроли, audit trails, evidence exports | Не храним секреты, не отправляем ордера |
| **GDPR** | Telemetry redaction, EU data residency | Минимизация персональных данных |
| **DORA** | Vendor pack, change control, incident docs | Не клеймим certification |
| **EU AI Act** | Model provenance, local approvals | Не "советник", нет персональных рекомендаций |

> CustodiaCloud — это B2B software/ICT продукт для профессиональных торговых организаций. CustodiaCloud не предоставляет инвестиционные советы, портфельное управление или торговые рекомендации. Live-исполнение происходит только через Agent под контролем клиента и через собственные брокерские счета клиента.

## Почему сейчас

1. **Регуляторный push**: усиление требований к governance и best execution (MiFID II, DORA)
2. **Зрелость ML-фреймворков**: production-ready библиотеки для RL
3. **Сложность рынков**: multi-asset стратегии требуют sophisticated tools
4. **Talent availability**: квантовый talent ищет современные платформы
